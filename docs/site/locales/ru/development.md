# Разработка

## Как устроен код

| Компонент | Назначение |
| --- | --- |
| `Program.cs` | Инициализация WinForms, проверка единственного экземпляра, открытие главного окна. |
| `MainDashboardForm.cs` | Жизненный цикл окна, команды трея, настройки и горячие клавиши. |
| `MainDashboardForm.Layout.cs` | Создание элементов управления и адаптация к размеру окна и DPI. |
| `MainDashboardForm.Capture.cs` | Скрытие окна, захват экрана и анализ палитры с возможностью отмены. |
| `MainDashboardForm.Palette.cs` | Выбор цвета, обновление инспектора, копирование и экспорт. |
| `ScreenOverlayForm` | Хранение снимка и выбор точки или области. Часть `.Painting.cs` рисует интерфейс выбора. |
| `Forms/Controls` | Отрисовка элементов управления, виртуальных строк палитры и полос прокрутки. |
| `Services` | Подготовка захвата, гистограмма, экспорт, проверка данных и горячие клавиши Windows. |
| `Models` | Настройки, сочетания клавиш и представления цветов. |

Захват использует физические экранные координаты: на дополнительных мониторах они могут быть отрицательными. Координаты снимка отсчитываются от левого верхнего угла виртуального рабочего стола. При изменении выбора пикселя учитывайте различие этих систем координат.

Окно выбора владеет снимком и вырезанным изображением. Главное окно копирует выбранную область для последующего анализа; каждая фоновая задача получает отдельную копию. Номер запроса не позволяет устаревшему результату перезаписать новый выбор.

## Сборка и тестирование

```powershell
dotnet restore ChromaTray.Tests/ChromaTray.Tests.csproj --locked-mode
dotnet test ChromaTray.Tests/ChromaTray.Tests.csproj -c Release --no-restore
```

Полный набор тестов требует Windows. На Linux/macOS запустите `ChromaTray.Core.Tests/ChromaTray.Core.Tests.csproj`: он проверяет общие алгоритмы цветов, гистограммы, навигации и экспорта. Linux также может компилировать Windows-проект благодаря настройке `EnableWindowsTargeting`.

## Сборка документации

Установите .NET 8 SDK и Python 3. Из корня репозитория выполните:

```powershell
dotnet tool restore
dotnet restore ChromaTray.csproj --locked-mode
python scripts/build-docs.py
```

На Linux/macOS при необходимости замените `python` на `python3`. Готовый сайт появится в `artifacts/docs-site`. Для локального просмотра:

```powershell
dotnet docfx serve artifacts/docs-site --port 8080
```

Откройте `http://localhost:8080/ru/`. Английская версия находится в корне сайта, переводы — в `/sk/`, `/cs/`, `/ru/` и `/uk/`. У каждого языка отдельный поисковый индекс. Переводы руководств находятся в `docs/site/locales/<язык>`, строки интерфейса — в `template/token.json` внутри той же папки. Общий шаблон добавляет переключатель с сохранением страницы.

API-метаданные и HTML генерируются автоматически и исключены из Git. Версия DocFX закреплена в `.config/dotnet-tools.json`. Меняйте комментарии `/// <summary>`, `<param>` и `<returns>` в C#, чтобы обновлять английские описания API. Обычные комментарии `//` остаются в исходниках. Справочник показывает публичные типы и члены; эта страница также объясняет внутренние компоненты.

## Автоматическое обновление

Workflow **Documentation** собирает все языки при изменениях и pull request, затем сохраняет сайт в артефакте `documentation-site`. Проверка pull request не публикует сайт.

Для автоматической публикации в GitHub Pages администратору репозитория нужно один раз:

1. В **Settings → Pages** выбрать **Source: GitHub Actions**.
2. Открыть **Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**. Указать имя `DOCS_PUBLISH_ENABLED` и значение `true`.
3. Запустить workflow **Documentation** или отправить изменение документации либо кода в `main`.

После настройки успешные сборки `main` публикуют сайт; адрес отображается в окружении развёртывания workflow. Без настройки полный сайт остаётся доступным в артефакте для скачивания.
