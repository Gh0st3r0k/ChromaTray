# Розробка

## Будова коду

| Компонент | Призначення |
| --- | --- |
| `Program.cs` | Ініціалізація WinForms, перевірка єдиного екземпляра, відкриття головного вікна. |
| `MainDashboardForm.cs` | Життєвий цикл вікна, команди трея, налаштування та гарячі клавіші. |
| `MainDashboardForm.Layout.cs` | Створення елементів керування й адаптація до розміру вікна та DPI. |
| `MainDashboardForm.Capture.cs` | Приховування вікна, захоплення екрана й аналіз палітри з можливістю скасування. |
| `MainDashboardForm.Palette.cs` | Вибір кольору, оновлення інспектора, копіювання та експорт. |
| `ScreenOverlayForm` | Зберігання знімка й вибір точки або області. Частина `.Painting.cs` малює інтерфейс вибору. |
| `Forms/Controls` | Малювання елементів керування, віртуальних рядків палітри та смуг прокручування. |
| `Services` | Підготовка захоплення, гістограма, експорт, перевірка даних і гарячі клавіші Windows. |
| `Models` | Налаштування, сполучення клавіш і представлення кольорів. |

Захоплення використовує фізичні екранні координати: на додаткових моніторах вони можуть бути від’ємними. Координати знімка відраховуються від верхнього лівого кута віртуального робочого стола. Змінюючи вибір пікселя, враховуйте різницю між цими системами координат.

Вікно вибору володіє знімком і вирізаним зображенням. Головне вікно копіює вибрану область для подальшого аналізу; кожне фонове завдання отримує окрему копію. Номер запиту не дозволяє застарілому результату перезаписати новий вибір.

## Збірка й тестування

```powershell
dotnet restore ChromaTray.Tests/ChromaTray.Tests.csproj --locked-mode
dotnet test ChromaTray.Tests/ChromaTray.Tests.csproj -c Release --no-restore
```

Повний набір тестів потребує Windows. На Linux/macOS запустіть `ChromaTray.Core.Tests/ChromaTray.Core.Tests.csproj`: він перевіряє спільні алгоритми кольорів, гістограми, навігації та експорту. Linux також може компілювати Windows-проєкт завдяки налаштуванню `EnableWindowsTargeting`.

## Збірка документації

Установіть .NET 8 SDK та Python 3. З кореня репозиторію виконайте:

```powershell
dotnet tool restore
dotnet restore ChromaTray.csproj --locked-mode
python scripts/build-docs.py
```

На Linux/macOS за потреби замініть `python` на `python3`. Готовий сайт з’явиться в `artifacts/docs-site`. Для локального перегляду:

```powershell
dotnet docfx serve artifacts/docs-site --port 8080
```

Відкрийте `http://localhost:8080/uk/`. Англійська версія розташована в корені сайту, переклади — у `/sk/`, `/cs/`, `/ru/` та `/uk/`. Кожна мова має власний пошуковий індекс. Переклади посібників розміщені в `docs/site/locales/<мова>`, рядки інтерфейсу — у `template/token.json` у тій самій папці. Спільний шаблон додає перемикач зі збереженням сторінки.

API-метадані та HTML генеруються автоматично й виключені з Git. Версія DocFX зафіксована в `.config/dotnet-tools.json`. Змінюйте коментарі `/// <summary>`, `<param>` і `<returns>` у C#, щоб оновлювати англійські описи API. Звичайні коментарі `//` залишаються у вихідному коді. Довідник показує публічні типи та члени; ця сторінка також пояснює внутрішні компоненти.

## Автоматичне оновлення

Workflow **Documentation** збирає всі мови після змін і для pull request, а потім зберігає сайт в артефакті `documentation-site`. Перевірка pull request не публікує сайт.

Для автоматичної публікації в GitHub Pages адміністратору репозиторію потрібно один раз:

1. У **Settings → Pages** вибрати **Source: GitHub Actions**.
2. Відкрити **Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**. Указати назву `DOCS_PUBLISH_ENABLED` і значення `true`.
3. Запустити workflow **Documentation** або надіслати зміну документації чи коду в `main`.

Після налаштування успішні збірки `main` публікують сайт; адреса відображається в середовищі розгортання workflow. Без налаштування повний сайт залишається доступним в артефакті для завантаження.
